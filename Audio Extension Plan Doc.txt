Web extension that acts as an on site audio splitter and mixer


Able to remove background music from YouTube videos, shorts, Tik toks, ect.

Able to split audio files into frequency categories: Bass, Drums/ percussion, vocal, melody (sub categories by instrument like piano, guitar, brass, woodwind, ect. If possible)

Able to record browser audio

Able to add various effects to the audio the user is listening to via browser like bass boosted, slowed, sped up, and stacked with things like reverb, chorus, vinyl filter, ect. 

Possibly able to replace background music with the users own choice in music via connecting to platforms like Spotify, Apple Music, etc.


What Currently Exists (The Pieces)
	•	Stem Separation (Removing BGM, isolating bass/vocals/drums): This technology exists and is widely used, but mostly as standalone web applications or desktop software (e.g., Moises, LALAL.AI, Fadr, or open-source tools like Spleeter and Demucs). You usually have to upload an audio file or paste a YouTube link, wait for the AI to process it, and then download the stems.  
	•	Browser Audio Effects (EQ, Bass Boost, Reverb): There are several Chrome extensions that intercept browser audio to add effects. Extensions like Ears: Bass Boost, EQ Any Audio, or Audio Channel use the browser's Web Audio API to manipulate HTML5 audio/video tags in real-time.  
	•	Audio Recording: Extensions like Chrome Audio Capture or Sample easily allow users to record the output of their current browser tab.  
	•	Speed Adjustment: Extensions like Global Speed or Video Speed Controller handle slowing down or speeding up media seamlessly.  
2. The Technical Reality (Why it isn't an extension yet)
The main reason your idea doesn't exist as a unified, real-time web extension is the computational power required for live AI stem separation.
	•	The Bottleneck: Adding a vinyl filter or a bass boost requires very little processing power; the browser's native Web Audio API handles it easily. However, separating an audio track into vocals, drums, bass, and melody requires running the audio through a complex neural network.  
	•	Real-time vs. Post-processing: Doing this in real-time (as a TikTok or YouTube video is playing) without causing massive latency, audio stuttering, or melting the user's CPU/RAM is incredibly difficult inside a browser extension.
	•	Browser Limitations: Extensions are sandboxed and historically haven't had the raw access to GPU power needed for heavy AI inference, though modern technologies like WebGPU and WebAssembly (WASM) are starting to change this.

Week 4: Polish & Bug Fixing. Audio programming is notoriously finicky. You will spend this week fixing bugs, like audio drifting out of sync, the extension crashing on certain websites, or the UI looking weird.

Project Master Blueprint: In-Browser Audio Mixer & Stem Splitter
1. The Tech Stack & Architecture
You are building three separate but connected pieces of software.
A. The Frontend: Chrome Extension (Manifest V3)
	•	Languages: HTML, CSS, JavaScript (or a lightweight framework like React/Vue if you prefer, but Vanilla JS is easier for a V1).
	•	Core API: chrome.tabCapture API (to grab the audio from the current tab).
	•	Purpose: The UI the user interacts with (sliders, buttons) and the script that injects your custom audio player over the webpage.
B. The Local Audio Engine
	•	Core Tech: Web Audio API (Native to the browser).
	•	Purpose: Handles all the instant effects for free on the user's Mac.
	•	Capabilities: BiquadFilterNode for Bass Boost/EQ, ConvolverNode for Reverb, playbackRate for speed adjustment, and MediaRecorder for capturing the final output.
C. The AI Backend (The Heavy Lifter)
	•	Language: Python.
	•	Framework: FastAPI (Lightning-fast API framework to handle the frontend requests).
	•	AI Model: Demucs (Meta's open-source model) or Spleeter (Deezer's model). Demucs has better quality; Spleeter is faster.
	•	Hosting: Run locally on your Mac for testing. Later, deploy to Modal, RunPod, or AWS for production GPUs.

3. Critical Unstated Concerns (The "Gotchas")
Before you write a single line of code, you need to decide how to handle these massive technical hurdles. Ask your AI assistant to help you strategize around these:
A. How do you actually get the audio to your server?
	•	The Problem: You can't easily send a "live continuous stream" to an AI model for stem separation. The model needs a complete file to analyze.
	•	Question to solve: Do you use a third-party API (like yt-dlp in your backend) to download the YouTube audio directly via the URL instead of recording it via the browser? (Warning: This violates YouTube's Terms of Service, though many apps do it). Or do you have the extension record the first 30 seconds of the tab, send that chunk, and process it?
B. The Synchronization Nightmare
	•	The Problem: If a user is watching a YouTube video, clicks "Isolate Vocals", and you send the audio to your server, it might take 15 seconds to process. When the stems come back, the YouTube video is now 15 seconds ahead.
	•	Question to solve: How do you sync the returning audio stems with the video player? Do you pause the video while processing? Do you mute the original YouTube player and mathematically sync your custom Web Audio API stems to the YouTube video's exact timestamp?
C. CORS (Cross-Origin Resource Sharing)
	•	The Problem: Browsers block web pages from requesting data from different domains for security reasons. Your extension (running on youtube.com) trying to talk to your Python backend (localhost:8000 or your-api.com) will get blocked immediately.
	•	Question to solve: You must configure your FastAPI backend to explicitly allow CORS requests from your Chrome Extension's unique ID.
D. Memory Leaks
	•	The Problem: Holding 4 high-quality, uncompressed audio stems (vocals, bass, drums, melody) in the browser's RAM via the Web Audio API can crash the user's tab if the song is 10 minutes long.
	•	Question to solve: How will you manage the audio buffer size?
